== 緒言
* AutoHotkey v2 用のキーカスタマイズスクリプト。
* **「Space」キーなどのモディファイア化**:
** 単押し（タップ）では通常の Space として動作し、他キーとの組み合わせでは修飾キー（レイヤー切り替え）として機能する。
** 短押し判定のしきい値（デフォルト200ms）などはスクリプト内で調整可能となる。
* **高いカスタマイズ性**:
** 各機能の有効/無効化や、詳細な設定変更を推奨する。
** 多機能かつ実験的な要素も含まれているため、自身の環境に合わせた「ベースサンプル」としての利用を想定している。
** Dvorak、Colemak、オリジナル配列など、多種多様なキーレイアウトに柔軟に対応可能。
* **日本語環境への最適化**:
** JIS配列キーボードでの利用を前提としていますが、キー数の少ない US キーボード等への応用も効果的。
** 「Caps Lock」や「ひらがな/カタカナ」キーの挙動を安定させるため、レジストリ等でスキャンコードを F13, F14 等に書き換えて運用している。なお、PowerToys等の設定変更ツールを使用しても挙動が安定するという話を聞いたが試してはいない。

=== キーロガー (KeyLogger)
タイピングの統計（3キーシーケンス（トリグラム）の出現頻度と打鍵間隔）を記録します。
各配列の効率分析や、自身のタイピング傾向の把握に活用できます。

* **セキュリティ配慮**: パスワード等の入力を避けるため、**IME ON（日本語入力時）のみ**動作するように設計されています。
* **操作**: [Win] + [.] で機能の ON/OFF を切り替え可能です。
* **データ保存**: 統計結果は `log.txt` に出力されます。

=== IME インジケーター (Dot Indicator)
現在の IME 状態を視覚化します。日本語入力が ON の間、マウスカーソルに追従する小さなドットを表示します。

* **操作**: [Win] + [,] でインジケーターの表示/非表示を切り替え可能です。

=== その他機能
* **サスペンド** : [F13] + [Alt] + [Enter] でスクリプトの一時停止
* **マウス速度制御**: [Win] + [Up/Down] でシステムのマウスカーソル速度を変更
* **IME制御**:
** [F14] / [変換] で IME トグル
** [Shift] + [全角] で 英数
* **ヘルプ** : [F13] + [Win] + [h]で ヘルプを表示

== config.ini の設定とカスタムレイアウト仕様

`config.ini` を編集することで、キーレイアウトや各種レイヤーのマッピングを動的にカスタマイズできます。
設定ファイルには共通設定を行う `[Settings]` セクションと、各レイアウト定義セクション（`[1]`, `[2]`, `[3]` ...）が存在します。

=== 共通設定 (`[Settings]`)
[horizontal]
StartupLayout:: 起動時に適用するレイアウト名（例: `Qwerty`, `Oonishi`, `FMIX13f-Kanade` など）。
HoldTh:: 通常キーの長押しと判定する閾値（ミリ秒、デフォルト: `300`）。
LayerHoldTh:: レイヤーキー長押し判定（レイヤー切り替え）の閾値（ミリ秒、デフォルト: `150`、内部で `Layers.HoldTh` に反映）。
b_time:: 同時押し（Mode=7）における待機判定の遊び時間（ミリ秒、デフォルト: `50`、内部で `LKey.b_time` に反映）。
ImeIndicatorEnabled:: IMEインジケーター（マウス追従ドット）の表示 (`1`) / 非表示 (`0`)。
LogEnabled:: キーロガーの有効化 (`1`) / 無効化 (`0`)。
MaxLog:: キーロガーの最大保存件数（デフォルト: `5000`）。
space, noconv, conv, tab, f13, f14:: 各モディファイアキーに対応する動的カスタムレイヤー定義のセクション名（例: `space = NAVI_CTRL`）。指定された場合、対応するキーを押している間のレイヤーに、指定セクション内のキーマッピングが動的に上書き・追加適用されます。

=== レイアウト定義（バージョン 2 形式 `ver = 2`）
IME OFF時とIME ON時のキー定義セクションを分離し、より柔軟なモード指定や同時押し（コンビネーション）を設定できる高度な仕様です。

==== 1. 親セクション定義（`[2]` など）
対象のレイアウト番号セクション（例: `[2]`）で、使用するバージョンや配列定義セクションを紐づけます。
[horizontal]
ver:: バージョン。`2` を指定します。ver1の利用は非推奨
Name:: レイアウトの識別名（例: `FMIX13f-Kanade`）。
Layout:: IME OFF時の配列を定義したセクション名（例: `FMIX13`）。
LayoutIME:: IME ON時の配列を定義したセクション名（例: `Kanade`）。省略時は `Layout` セクションと同じ定義が使用されます。

==== 2. 配列定義セクション（`[FMIX13]` や `[Kanade]` など）
`Layout` および `LayoutIME` で指定した各セクション内で、具体的なキー配置や挙動を設定します。

===== A. モード指定
* *`Mode`*: このレイアウトで使用する `LKey` の動作モードを指定します（デフォルト: `1`）。
** `Mode=1`: 置換モード（短押しでリマップ文字入力、長押しでBackspace後にシフトしたキーを再入力）。
** `Mode=4`: コンビネーション優先モード（短押しでリマップ文字、長押しで対応するレイヤー修飾）。
** `Mode=7`: コンビネーション優先モード（誤爆防止のタイミング制御拡張版）。修飾キーを押し下げてから `LayerHoldTh`（ミリ秒、デフォルト: `150`）経過後にメインキーが押された場合に修飾キーのコンビネーション（同時押し動作）として機能し、`(LayerHoldTh - b_time)` ms（`b_time` デフォルト: `50`）未満の高速打鍵時はメインキーの通常入力動作とします。その間（`LayerHoldTh - b_time` ms 以上 `LayerHoldTh` ms 未満）にメインキーが押された場合は残り時間待機し、修飾キーが押され続けていればコンビネーション、離されたら通常キーを送信します。

===== B. 基本・状態別配列定義
JISキーボードの4段に対応する行ごとのスペース区切り文字列によって、全体のキー配列を定義します。

* *`L00` 〜 `L03`*: 通常配列 (Shift OFF)
* *`S00` 〜 `S03`*: Shift配列 (Shift ON)

各行に定義するキーの個数とQWERTY配列での対応位置は以下の通りです（計48キー）：
[cols="1,2,3"]
|===
|行識別子 |対応する段 (キー数) |デフォルトのQWERTYキー順

|`00`
|数字・記号段 (13キー)
|`1 2 3 4 5 6 7 8 9 0 - ^ \`

|`01`
|QWERTY段 (12キー)
|`q w e r t y u i o p @ [`

|`02`
|ASDF段 (12キー)
|`a s d f g h j k l ; : ]`

|`03`
|ZXCV段 (11キー)
|`z x c v b n m , . / \`
|===

===== C. 同時押し（コンビネーション）定義
`Mode=7` または `Mode=4` で動作するキー同士の同時押しマッピングを、セクション内に直接追加できます（INIから読み込まれる同時押し定義はデフォルトで `Mode=7` として登録されます）。
* *記述形式*: `m_[修飾キー(物理キー名)]+[対象キー(物理キー名)] = [出力文字列]`
* *記述例*: `m_r+p = areru` (物理キー `r` と `p` を同時押しした際、`areru` を送信)
* *連続打鍵設定*: `|`（パイプ）記号を用いて `m_r+e = ru|{BS}rareru` のように定義することで、同時押し時においても1回目（`ru`）と2回目以降の連続打鍵時（`{BS}rareru`）で送信するキーを分けることができます。
* ※ IME ON時/OFF時いずれのセクションでもプレフィクスは `m_` で統一します。

===== D. 個別キーのオーバーライド設定
行定義の上から、特定の物理キーに対してピンポイントでキーマップの上書き（単キー/ショートカット/特殊送出）が可能です。
キー名には、元のQWERTY配列での役割に応じた定義名を使用します。

* *個別キー記述名*: 例として `semicolon` (`;`), `colon` (`:`), `comma` (`,`), `noconv` (無変換), `conv` (変換) など。
* *自動パース（記述の簡略化）*: INIファイル上の値設定で、1文字の危険な記号・修飾記号（`+` や `*` など）を自動検知して安全な形式（ `{}` 囲み）にエスケープする機能を備えているため、`semicolon = :` や `s_semicolon = +` のように素のままで記述できます。
* *個別キー用の状態プレフィックス*:
** プレフィックスなし: 通常時
** `s_`: Shift押下時

=== 3. レイヤー配列のカスタマイズ

レイヤーのカスタマイズ方法には、**レイアウト定義に応じた自動読み込み**と、**動的カスタムレイヤーによる個別の上書き・追加**の2通りがあります。

==== A. レイアウト連動型の自動読み込み (`ver = 2` 時)
`ver = 2` のレイアウトがロードされる際、`config.ini` 内に以下の固定のレイヤー用セクションが定義されていると、各レイヤーのアクションが自動的に読み込まれ適用されます。

* **`[NAVI_CTRL]`**: ナビゲーションレイヤー（F13長押し等。レイヤーID: `1`）
* **`[SYMBOL_NUM]`**: 記号・数値レイヤー（無変換長押し等。レイヤーID: `2`）
* **`[SYMBOL1]`**: 記号レイヤー1（変換長押し等。レイヤーID: `3`）
* **`[SYMBOL2]`**: 記号レイヤー2（F14長押し等. レイヤーID: `4`）
* **`[SELECT]`**: 選択レイヤー（F13+Alt / 無変換同時押し等。レイヤーID: `5`）
* **`[NUMPAD]`**: テンキーレイヤー（Tab長押し等。レイヤーID: `6`）

==== B. 動的カスタムレイヤーの設定（全レイアウト共通）
`[Settings]` セクションでモディファイアキーと任意のセクション名を紐づけることで、そのモディファイアキーに対応するレイヤー配列に対して、指定したセクションのマッピングを動的に上書き・追加できます。

* **設定手順**:
  1. `[Settings]` セクションに `space = NAVI_CTRL` のように、モディファイアキーと任意のセクション名を定義。
  2. 定義したセクション（例: `[NAVI_CTRL]`）を作成し、キーバリュー形式でマッピングを記述。
* **対象モディファイアキー**: `space`, `noconv`, `conv`, `tab`, `f13`, `f14`

==== C. レイヤーマッピングの記述形式
各レイヤーセクション内では、メイン配列定義セクションと同様に `L00` 〜 `L03` で4段を一括設定することも、物理キー名を左辺として個別キー単位でオーバーライドすることも可能です。
値の右辺には、`ResolveKeyText()` により自動解決されるため、通常の文字（`a` 等）や `+` などの記号、`{Left}` や `^a` などの特殊表記・ショートカットをそのまま記述できます。

また、`|`（パイプ）記号を用いて `アクション1|アクション2` のように定義することで、修飾キーを押したままそのキーを叩いた回数に応じて、**1回目**と**2回目以降の連続打鍵時**で送信されるキーを分けることができます。

* **動作例**: `j = {Left}|{Home}` と設定した場合、修飾キーを押したまま `j` を1回押すと `{Left}` が送信され、そのまま `j` を2回以上連続で叩くと `{Home}` が送信されます。
* **リセット規則**: 修飾キーを一度離すか、または間に他のキー入力が挟まると連続打鍵状態はクリアされ、次回打鍵時は再び1回目のキーが送信されます。

##### 記述例
[source,ini]
----
[Settings]
space = NAVI_CTRL
noconv = SHORTCUT_CTRL

[NAVI_CTRL]
; space 長押しレイヤー時のカーソル・編集キーマッピング個別上書き
h = {Left}
j = {Down}
k = {Up}
l = {Right}
u = {Home}
o = {End}
n = {BackSpace}

[SHORTCUT_CTRL]
; noconv 長押しレイヤー時のショートカット個別上書き
a = ^a
s = ^s
c = ^c
v = ^v
----
