== 緒言
* AutoHotkey v2 用のキーカスタマイズスクリプト: 律(仮称)。
* **「Space」キーなどの修飾キー(モディファイアキー)化**:
** 単押し（タップ）では通常の Space として動作し、他キーとの組み合わせでは修飾キー（レイヤー切り替え）として機能する。
** 短押し判定のしきい値（デフォルト200ms）などはスクリプト内で調整可能となる。
* **高いカスタマイズ性**:
** 各機能の有効/無効化や、詳細な設定変更を推奨する。
** 多機能かつ実験的な要素も含まれているため、自身の環境に合わせた「ベースサンプル」としての利用を想定している。
** Dvorak、Colemak、オリジナル配列など、多種多様なキー配列(キーレイアウト)に柔軟に対応可能。
* **日本語環境への最適化**:
** JIS配列キーボードでの利用を前提としていますが、キー数の少ない US キーボード等への応用も効果的。
** 「Caps Lock」や「ひらがな/カタカナ」キーの挙動を安定させるため、レジストリ等でスキャンコードを F13, F14 等に書き換えて運用している。なお、PowerToys等の設定変更ツールを使用しても挙動が安定するという話を聞いたが試してはいない。

== config.ini の設定とカスタムキー配列(カスタムレイアウト)仕様

`config.ini` を編集することで、キー配列や各種レイヤーのマッピングを動的にカスタマイズできます。
設定ファイルには共通設定を行う `[Settings]` セクションと、各キー配列定義セクション（`[1]`, `[2]`, `[3]` ...）が存在します。

=== 共通設定 (`[Settings]`)
[horizontal]
StartupLayout:: 起動時に適用するキー配列名（例: `Qwerty`, `Oonishi`, `FMIX13f-Kanade` など）。
HoldTh:: 通常キーの長押しと判定するしきい値（ミリ秒、デフォルト: `300`）。
LayerHoldTh:: レイヤーキー長押し判定（レイヤー切り替え）のしきい値（ミリ秒、デフォルト: `150`、内部で `Layers.HoldTh` に反映）。
b_time:: 同時押し（Mode=7）における待機判定の遊び時間（ミリ秒、デフォルト: `50`、内部で `LKey.b_time` に反映）。
b_time2:: 同時押し（Mode=8）における待機判定の遊び時間（ミリ秒、デフォルト: `50`、内部で `LKey.b_time2` に反映）。
ImeIndicatorEnabled:: IMEインジケーター（マウス追従ドット）の表示 (`1`) / 非表示 (`0`)。
LogEnabled:: キーロガーの有効化 (`1`) / 無効化 (`0`)。
MaxLog:: キーロガーの最大保存件数（デフォルト: `5000`）。
space, noconv, conv, tab, f13, f14:: 各修飾キーに対応する動的カスタムレイヤー定義のセクション名（例: `space = NAVI_CTRL`）。指定された場合、対応するキーを押している間のレイヤーに、指定セクション内のキーマッピングが動的に上書き・追加適用されます。

=== キー配列定義（バージョン 2 形式 `ver = 2`）
IME OFF時とIME ON時のキー定義セクションを分離し、より柔軟なモード指定や同時押しを設定できる高度な仕様です。

==== 1. 親セクション定義（`[2]` など）
対象のキー配列番号セクション（例: `[2]`）で、使用するバージョンや配列定義セクションを紐づけます。
[horizontal]
ver:: バージョン。`2` を指定します。ver1の利用は非推奨
Name:: キー配列の識別名（例: `FMIX13f-Kanade`）。
Layout:: IME OFF時の配列を定義したセクション名（例: `FMIX13`）。
LayoutIME:: IME ON時の配列を定義したセクション名（例: `Kanade`）。省略時は `Layout` セクションと同じ定義が使用されます。

==== 2. 配列定義セクション（`[FMIX13]` や `[Kanade]` など）
`Layout` および `LayoutIME` で指定した各セクション内で、具体的なキー配置や挙動を設定します。

===== A. モード指定
* *`Mode`*: このキー配列で使用する `LKey` の動作モードを指定します（デフォルト: `1`）。
** `Mode=1`: 置換モード（短押しでリマップ文字入力、長押しでBackspace後にシフトしたキーを再入力）。
** `Mode=4`: 同時押し優先モード（短押しでリマップ文字、長押しで対応するレイヤー修飾）。
** `Mode=7`: 同時押し優先モード（誤爆防止のタイミング制御拡張版）。修飾キーを押し下げてからの経過時間 `t` としきい値 `LayerHoldTh` （デフォルト: `150` ms）、および遊び時間 `b_time` （デフォルト: `50` ms）に基づき、以下の3条件で動作します。
*** *条件1* (t >= LayerHoldTh): 修飾キーの同時押しを即座に送信。
*** *条件2* (t < LayerHoldTh - b_time): メインキーの通常キー（単体アクション）を即座に送信（Down時確定）。
*** *条件3* (LayerHoldTh - b_time <= t < LayerHoldTh): 判定を一時保留し、その後の入力状況に応じて挙動を確定させます。
**** *ケース3-A*: メインキーが先にUp（短押し）された場合 -> メインキー of 通常キーを送信。
**** *ケース3-B*: メインキーはHoldのまま、先に修飾キーがUpされた場合 -> メインキー of 通常キーを送信。
**** *ケース3-C*: 両キーともHoldのまま、経過時間(t)が LayerHoldTh を超えた場合 -> しきい値に達した瞬間に修飾キーの同時押しの送信へ切り替え。
** `Mode=8`: タイミング制御付き同時押し（短押しで即時送信、長押しで修飾、先行離鍵で同時押し判定を行う拡張モード）。遊び時間として `b_time2` を使用し、メインキー（同時押しされる対象キー）が先に離された場合（先行離鍵）でも同時押しを成立させます。


===== B. 基本・状態別配列定義
JISキーボードの4段に対応する行ごとのスペース区切り文字列によって、全体のキー配列を定義します。

* *`L00` 〜 `L03`*: 通常配列 (Shift OFF)
* *`S00` 〜 `S03`*: Shift配列 (Shift ON)

各行に定義するキーの個数とQWERTY配列での対応位置は以下の通りです（計48キー）：
[cols="1,2,3"]
|===
|行識別子 |対応する段 (キー数) |デフォルトのQWERTYキー順

|`00`
|数字・記号段 (13キー)
|`1 2 3 4 5 6 7 8 9 0 - ^ \`

|`01`
|QWERTY段 (12キー)
|`q w e r t y u i o p @ [`

|`02`
|ASDF段 (12キー)
|`a s d f g h j k l ; : ]`

|`03`
|ZXCV段 (11キー)
|`z x c v b n m , . / \`
|===

===== C. 同時押し定義
同時押し定義をセクション内に追加し、連続打鍵数に応じたアクション（最大3段階）や、キーごとの判定しきい値・待機時間の個別微調整を行えます。

* *記述形式 1 (判定時間微調整あり)*: `m_[修飾キー]+[対象キー] = "mode[,hold_th][,b_time]",action1[,action2][,action3]`
** 例: `m_s+d = "8,250,75",myaction1,myaction2,myaction3`
** 動作モード `mode`、判定しきい値 `hold_th` (ms)、および待機遊び時間 `b_time` (ms) をダブルクォーテーションで囲んでカンマ区切りで記述し、その後に送信するアクションを最大3段階まで定義できます。
* *記述形式 2 (判定時間微調整なし)*: `m_[修飾キー]+[対象キー] = mode,action1[,action2][,action3]`
** 例: `m_r+p = 7,areru`
** モード `mode` とアクションを直接指定します。しきい値や遊び時間が省略された場合は、それぞれ `LayerItem` の標準値（`Layers.hold_th` およびモード別の標準遊び時間）が適用されます。
* *省略時デフォルト*: `action2`, `action3` は省略可能で、省略時は空文字 `""` が自動的に設定されます。
* *後方互換形式*: `m_[修飾キー]+[対象キー] = [出力文字列]`
** 例: `m_a+s = abc` (従来の書き方)
** 動作モードは自動的に `7` に設定され、アクション1: `abc`、アクション2・3: `""` として処理されます。
* ※ IME ON時/OFF時いずれのセクションでもプレフィクスは `m_` で統一します。

===== D. 個別キーのオーバーライド設定
行定義の上から、特定の物理キーに対してピンポイントでキーマップの上書き（単キー/ショートカット/特殊送出）が可能です。
キー名には、元のQWERTY配列での役割に応じた定義名を使用します。

* *個別キー記述名*: 例として `semicolon` (`;`), `colon` (`:`), `comma` (`,`), `noconv` (無変換), `conv` (変換) など。
* *自動パース（記述の簡略化）*: INIファイル上の値設定で、1文字の危険な記号・修飾記号（`+` や `*` など）を自動検知して安全な形式（ `{}` 囲み）にエスケープする機能を備えているため、`semicolon = :` や `s_semicolon = +` のように素のままで記述できます。
* *個別キー用の状態プレフィックス*:
** プレフィックスなし: 通常時
** `s_`: Shift押下時

=== 3. レイヤー配列のカスタマイズ

レイヤーのカスタマイズ方法には、**キー配列定義に応じた自動読み込み**と、**動的カスタムレイヤーによる個別の上書き・追加**の2通りがあります。

==== A. キー配列連動型の自動読み込み (`ver = 2` 時)
`ver = 2` のキー配列がロードされる際、`config.ini` 内に以下の固定のレイヤー用セクションが定義されていると、各レイヤーのアクションが自動的に読み込まれ適用されます。

* **`[NAVI_CTRL]`**: ナビゲーションレイヤー（F13長押し等。レイヤーID: `1`）
* **`[SYMBOL_NUM]`**: 記号・数値レイヤー（無変換長押し等。レイヤーID: `2`）
* **`[SYMBOL1]`**: 記号レイヤー1（変換長押し等。レイヤーID: `3`）
* **`[SYMBOL2]`**: 記号レイヤー2（F14長押し等. レイヤーID: `4`）
* **`[SELECT]`**: 選択レイヤー（F13+Alt / 無変換同時押し等。レイヤーID: `5`）
* **`[NUMPAD]`**: テンキーレイヤー（Tab長押し等。レイヤーID: `6`）

==== B. 動的カスタムレイヤーの設定（全キー配列共通）
`[Settings]` セクションで修飾キーと任意のセクション名を紐づけることで、その修飾キーに対応するレイヤー配列に対して、指定したセクションのマッピングを動的に上書き・追加できます。

* **設定手順**:
  1. `[Settings]` セクションに `space = NAVI_CTRL` のように、修飾キーと任意のセクション名を定義。
  2. 定義したセクション（例: `[NAVI_CTRL]`）を作成し、キーバリュー形式でマッピングを記述。
* **対象修飾キー**: `space`, `noconv`, `conv`, `tab`, `f13`, `f14`

==== C. レイヤーマッピングの記述形式
各レイヤーセクション内では、メイン配列定義セクションと同様に `L00` 〜 `L03` で4段を一括設定することも、物理キー名を左辺として個別キー単位でオーバーライドすることも可能です。
値の右辺には、`ResolveKeyText()` により自動解決されるため、通常の文字（`a` 等）や `+` などの記号、`{Left}` や `^a` などの特殊表記・ショートカットをそのまま記述できます。

また、`|`（パイプ）記号を用いて `アクション1|アクション2` のように定義することで、修飾キーを押したままそのキーを叩いた回数に応じて、**1回目**と**2回目以降の連続打鍵時**で送信されるキーを分けることができます。

* **動作例**: `j = {Left}|{Home}` と設定した場合、修飾キーを押したまま `j` を1回押すと `{Left}` が送信され、そのまま `j` を2回以上連続で叩くと `{Home}` が送信されます。
* **リセット規則**: 修飾キーを一度離すか、または間に他のキー入力が挟まると連続打鍵状態はクリアされ、次回打鍵時は再び1回目のキーが送信されます。

##### 記述例
[source,ini]
----
[Settings]
space = NAVI_CTRL
noconv = SHORTCUT_CTRL

[NAVI_CTRL]
; space 長押しレイヤー時のカーソル・編集キーマッピング個別上書き
h = {Left}
j = {Down}
k = {Up}
l = {Right}
u = {Home}
o = {End}
n = {BackSpace}

[SHORTCUT_CTRL]
; noconv 長押しレイヤー時のショートカット個別上書き
a = ^a
s = ^s
c = ^c
v = ^v
----

== UIについて

`ui` フォルダ内には、ブラウザで動作するビジュアル設定エディタ（`ui/index.html`）が同梱されています。複雑な `config.ini` の記述を手動で行うことなく、グラフィカルな画面で直感的にカスタマイズや管理を行うことができます。

=== 起動方法
1. `ui/index.html` をブラウザ（Chrome、Edgeなどの Chromium系ブラウザ推奨）で開きます。
2. 画面右上の「ファイルを開く」ボタンから、本リポジトリの `config.ini` を選択してロードします。
* ※ Chromium系ブラウザでは、File System Access API や IndexedDB により、一度許可したファイルへの直接上書き保存（オートロード/ダイレクトセーブ）が可能です。

=== 各画面・パネルの説明

==== 1. 一般設定 (Settings)
起動時に適用されるデフォルトキー配列（`StartupLayout`）や、各種判定のしきい値・遊び時間などを設定します。
* **起動時レイアウト (StartupLayout)**: 起動時に自動適用されるキー配列スロット。
* **通常キー長押ししきい値 (HoldTh)** / **レイヤーキー長押ししきい値 (LayerHoldTh)**: 長押し（Tap-Hold）判定用のミリ秒。
* **同時押し待機遊び時間 (b_time / b_time2)**: Mode 7 および新仕様 Mode 8 で使用される、同時押しのタイミング誤爆防止用の遊び時間（ミリ秒）。
* **IMEインジケーター有効 / キーロガー有効**: マウス追従インジケーターや打鍵統計の出力を有効化します。

==== 2. 動的レイヤー (Dynamic Layers)
`space` や `noconv` などの親キー(修飾キー)長押し時に、どのカスタムレイヤー（`NAVI_CTRL` や `SHORTCUT_CTRL` など）を動的に適用するかを一覧で紐付けます。

==== 3. キー配列スロット(レイアウトスロット) (Layout Slots)
AHKスクリプトから切り替え可能な「スロット（1, 2, ...）」を定義します。
* スロット名、**IME OFF 時のキー配列定義**（英数用キー配列）、**IME ON 時のキー配列定義**（かな入力用キー配列）を個別に指定して紐付けることができます。

==== 4. キー配列定義 (Key Layouts)
物理キー配列に対応したメインのキーマップ編集エリアです。
* **キー配列プレビュー**: 物理キーボードを模したビジュアル画面で、キーをクリックしてマップ先文字や `{Left}` などの特殊送信コマンドを入力・編集できます。「Shiftキー押下状態」のチェックを入れることで、Shift時の配列（`S00`〜`S03`）も個別に編集可能です。
* **同時押し定義 [Mode 4/7/8用]**:
  特定の2キーの同時押し（`m_x+y`）に対するアクションを登録します。新仕様に対応しており、以下の項目を設定できます。
  ** **モード設定**: `Mode 8` (タイミング制御・B先行離鍵)、`Mode 7`、`Mode 4` から選択。
  ** **しきい値・遊び時間**: 個別の `hold_th`、`b_time` を指定可能（省略時はデフォルト値）。
  ** **マルチアクション**: 通常（1打鍵目）、2打鍵目連続、3打鍵目連続のそれぞれに送信するアクション（`action1`, `action2`, `action3`）を記述できます。
* **個別オーバーライド**: 特定の物理キーのみ、行定義（`L00`〜`L03`）から外れて個別に動作を上書きする定義を指定します。
* **インポート/エクスポート**: 定義したキー配列単体を `.klt` ファイルとして保存・読み込みできます。

==== 5. 修飾キーレイヤー(モディファイアレイヤー)設定 (Modifier Layers)
親キー長押し時に有効になる、修飾キーレイヤー（`[NAVI_CTRL]` など）専用のキーマップをビジュアル編集します。こちらもキーをクリックするだけで簡単にマッピングを追加できます。

==== 6. Raw config.ini エディタ
`config.ini` の生のテキストデータを直接編集できます。「変更をビジュアル表示に適用」ボタンを押すことで、テキスト編集内容がビジュアル画面に反映されます。

=== 設定の保存方法
* UI上での一時的な編集内容は、画面右上の **「保存 (Save)」** ボタンをクリックすることで `config.ini` ファイルに書き込まれます。
* ブラウザのセキュリティ制限等で直接上書き保存（PUT / File System Access API）が行えない場合は、自動的に `config.ini` がダウンロードされますので、既存のファイルを上書き（置き換え）してください。
